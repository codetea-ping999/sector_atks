# 手法

## 1. 業種の判定（`sector_atks/sectors.py`）

ATT&CK のグループ（intrusion set）の記述文を文に分け、各文で標的を表す語（target, against, victim, compromise, intrusion, focus, breach, sectors, industries など）が最初に出た位置より後ろだけを対象に、13 業種のキーワードを探します。

- 帰属の記述（「国家安全部に帰属」「軍の部隊 74455」）や動機の記述（「financially motivated」）を業種と取り違えないための工夫です。
- 「finance」「technology」「media」のような一般語は、後ろに区切り（カンマ、and、sectors、companies など）が続くときだけ業種とみなします。
- 判定の根拠になった語句を `evidence` 列に残します。`group_sector_overrides.csv` で追加・削除できます。

## 2. 重み（`sector_atks/weights.py`）

業種 s のグループ集合を G_s とすると、

```
share_s(t) = |{g ∈ G_s : g が t を使う}| / |G_s|
lift_s(t)  = share_s(t) / share_全体(t)
score_s(t) = (1 − β) × share_s(t) + β × p(t)
```

- グループが技術を使うとは、グループ自身の「uses」関係か、そのグループに帰属したキャンペーンの「uses」関係があることです。ソフトウェア経由の関係は、ソフトウェアが複数グループで共有されるため含めません。
- 既定では技術（親技術）単位で集計し、サブ技術は親に寄せます。`--subtechniques` で分けられます。
- 偵察（reconnaissance）と資源開発（resource-development）だけに属する技術は、組織の内部で検知を検証できないため既定で除きます。
- score 上位 N（既定 20）を優先集合 T とし、合計が 1 になるように正規化したものが w_t です。
- p(t) は外部の出現頻度（CTID など）を最大値で割って 0〜1 にしたもの。β の既定は 0 です。

## 3. VDC（`sector_atks/vdc.py`）

- **D_t**：技術 t の手順ごとに基準日以前の最新の結果を取り、`detected` または `prevented` の割合。`--exclude-prevented` で防御のみ（アラートなし）を検知に数えないようにできます。
- **可視性**：結果が `none` 以外（何らかのログが残った）だった手順の割合。D が低いときに、足りないのがルールかログかを切り分けます。`log_sources.csv` に ATT&CK が挙げるログソースがあります。
- **F_t**：技術 t の最新の検証日からの経過日数 a に対し、step なら a ≤ 窓（既定 90 日）で 1、それ以外は 0。exp なら 0.5^(a / 半減期)。
- **申告ギャップ**：ルールがあると申告した技術の重みの合計 − VDC。
- **回帰率**：`--previous-as-of` の時点で D > 0 だった技術のうち、今の D が下がった技術の割合。
- **改善速度**：同じ手順が検知できなかった日から、次に検知できた日までの日数の平均。
- **優先度**：残り = w_t × (1 − D_t × F_t)。この値が大きい技術を直すほど VDC が大きく上がります。

未検証の技術は D = 0、F = 0 として数えます（検証していないものは検知できると見なさない）。

## 4. 妥当性への脅威

- 業種判定はキーワード推定で、誤判定と漏れがある。ATT&CK に載っているグループは公開報告が多いものに偏る。
- 「使うグループの割合」は報告の多さに引きずられる。実際の観測頻度（Sightings など）とは一致しない。
- 対象グループが少ない業種では重みが不安定になる。
- D_t は手順の数で頑健性を近似しており、手順の選び方に依存する。「アラートが出た」ことと「分析者が気づいて対応した」ことは別である。
